# 中断任务续跑方向修复

日期：2026-10-09。

## 行为

- 手动停止先发送安全输出，然后记录原路径、执行段、弧长进度、区域/轮次和地图/任务身份；不将中断轮次标记为完成。
- 同一进程、同任务和配置、机器人仍在停止位置 0.5 米内：地图修订和几何未变时恢复原路径，并限制位置投影到原执行段，避免落到邻近的旧作业线。
- 地图变化或显式重规划时：从旧路径寻找当前/下一条未完成的扫描轴向边，不从机器人朝向推断正负方向；中断轮次使用恢复起点、方向和原轮次终点。
- 已完成区域/轮次从输出路径中排除，之后的完整轮次仍保留原覆盖起终点。
- 每轮路径点单独复制，避免后续轮次覆盖之前轮次的 path_type 标签。
- 新任务、配置或地图对齐角/坐标系变化、移机超过 0.5 米、显式不同起终点不继承检查点。继续旧任务需要相同任务 ID。

## 范围

修改 scheduler_node.py、planner_adapter.py、models.py，新增 task_continuation.py 和两组离线测试；更新 scheduler README 和 AGENTS 索引。
此次没有修改 mst27 算法或 C++ ABI，没有修改 APP、协议和地图裁剪配置；mst27.py 原有未提交变更属于前一轮共享预处理优化。
检查点仅在调度进程内存中，进程重启后不续跑。停止之后开始会建立新的执行记录，原停止结果保留。
